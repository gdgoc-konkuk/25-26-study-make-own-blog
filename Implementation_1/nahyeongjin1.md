# 개발 1회차 스프린트 회고

## ☀️ 날짜

2025.11.24 (Mon)

## 📜 내 작업 요약

- 개발 편의 도구 husky, eslint, prettier 셋업
- github actions를 통한 CD 구축 (CI는 추후 테스트 코드 도입과 같이 구축)
- github actions를 통한 issue와 PR 연동
  - PR 제목과 설명에 이슈 정보 주입
- 디자인 시스템 셋업
- Header, Footer와 같이 모든 페이지에서 사용될 컴포넌트로 공통 레이아웃 생성
- Mock data로 홈페이지 구현

## 📜 내 작업 내용 중 가장 인상깊었던 부분 & 가장 배움이 컸던 부분

- 피그마에 variables나 styles를 export하여 tailwind의 utility class로 등록하여 작업이 편할 것 같다.
- 이슈, PR 템플릿과 github actions를 활용하니 태스크 관리, 브랜치 전략에 도움이 됐다.
- 스터디장님과 노션 연동 전략에 대해 얘기했었다.
  - 아마 나는 MVP 수준에서는 github actions로 dispatch를 발행시켜
  - 추가된 블로그 포스트의 slug로 커밋 메시지를 만들고
  - mdx 페이지를 만드는 방식으로 진행하지 않을까 싶음
  - 추후 자동화 방법을 찾아보는걸로 결정

## 📜 김석진님 작업 내용 중 인상깊었던 부분

- TNT(TS, Next.js, Tailwind)라는 템플릿을 따로 구축해둬서 이번 프로젝트가 아니더라도 프론트 스택이 동일한 프로젝트에서 재사용할 수 있는 점이 재밌었다.
- husky를 안 쓰고 github actions로 prettier를 실행하는 것도 흥미로웠다.
- TailwindCSS v3를 나는 써본 적이 없어서 나중에 설정이나 코드를 한 번 확인해보고 싶다.

## 📜 최준서님 작업 내용 중 인상깊었던 부분

- 결국 figma make를 사용했다.
- 프론트 코드도 전부 make에서 옮겨버린 상태라서 컴포넌트로 변환하는 작업이나 유지보수가 어려울 것 같다.
- 기존 계획과는 다르게 블로그를 카드 형식이 아니라 새로운 페이지로 이동하도록 구현하여 더 가독성 좋고 컨텐츠에 집중하기 좋아진 것 같다.
